# Synthetic Mini Cattle Genomic Benchmark

These files are **synthetic**, not records of real animals. They were moved here from `data/real_cattle/` on 11 September 2026 and renamed with a `synthetic_` prefix; the `PROVENANCE` file makes every loader report them as synthetic.

| File | Generated by |
|---|---|
| `synthetic_cattle_50k_population.bed/.bim/.fam` | `scripts/fetch_real_cattle_data.py` (`generate_mini_cattle_benchmark`, seed 2026) |
| `synthetic_cattle_carcass_phenotypes.csv` | same script |

What the generator does: 500 SNPs on 29 autosomes, breed allele frequencies drawn from Beta(2, 2), each offspring allele transmitted independently per SNP (no linkage, no recombination map), a 0.2 % genotyping-error rate, and phenotypes from an assumed additive + dominance model with assumed fixed effects for age, sex and feeding.

Consequences:

- Tests and outputs that use these files (`tests/test_transmission_trio.py`, `tests/test_real_data_ingestion.py`, `output/user_evaluation/`, `output/empirical/`) check the parsers and pipelines against a known generator. They are not empirical validation.
- Mendelian transmission checks on this data are circular: the generator applies Mendelian transmission by construction.
- There is no linkage, so no recombination or crossover statistic can be validated with it.
- The existing files were generated with the earlier QTL catalogue, whose citations turned out to be fabricated and whose marbling loci sat on wrong positions (e.g. TG on BTA15), and with a `"CarcassWeight"` filter that matched no locus (so no growth QTL were boosted). Both are fixed in the generator; the files were not regenerated because tests depend on their current content.

The real data used by the framework is in `data/real_cattle/florida_multibreed/` (University of Florida Angus–Brahman multibreed herd) and `data/real_cattle/spanish_trios/`.
